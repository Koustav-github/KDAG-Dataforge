# docs

Source documents and the generators that produce them. Everything here is
reproducible — edit the script, re-run, don't hand-edit the output.

| File | What it is |
|---|---|
| `concept-summary.pdf` | **The one-page concept summary required by the problem statement** (p.13). 790 words, 1 page. Generated by `make_concept_summary.py`. |
| `concept-summary.docx` | Editable source for the above. |
| `make_concept_summary.py` | Generates the concept summary. Judge-facing register: a briefing for a data scientist. |
| `BDH_Model_Surgery_Primer.docx` | Plain-language primer for the team — what BDH is, how merging works, why it is novel. Explicitly *not* the concept summary. |
| `make_primer.py` | Generates the primer. Newcomer register. |
| `assemble_submission.py` | Builds `submission/` — the hand-over package plus its checklist. |
| `Model_Surgery_Deck.pptx` | Presentation deck. |
| `Model_Surgery_Spec.docx` | The original design spec. |
| `Model_Surgery_Presentation_Content.docx` | Deck content in long form. |
| `superpowers/plans/` | The implementation plan the project was executed from. |

## Regenerating

```bash
# from repo root
uv run --with python-docx python docs/make_concept_summary.py   # -> concept-summary.docx
uv run --with python-docx python docs/make_primer.py            # -> primer .docx
uv run --with python-docx python docs/assemble_submission.py    # -> submission/
```

The `.docx` → `.pdf` step uses Word on Windows (`SaveAs` with `wdFormatPDF`);
any converter that preserves the one-page layout is fine. After regenerating the
concept summary, re-run `assemble_submission.py` so `submission/` picks it up.
